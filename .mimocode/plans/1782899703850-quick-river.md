# 通用通知系统重构计划

## 目标
将硬编码的 ntfy 通知替换为通用通知接口，支持多种通知渠道（ntfy、Telegram、Webhook），并增加 Markdown 开关。

## 当前实现分析

**通知发送位置**: `predictor.go:286-330` (`sendNtfyNotification`)
**配置结构**: `config.go:14-19` (`PushConfig` 仅含 ntfy 相关字段)
**调用点**:
- `predictor.go:272` - 天气预报推送
- `main.go:87` - 启动测试消息

## 设计方案

### 1. 新增 `notify.go` - 通知接口与实现

```go
// Notifier 通用通知接口
type Notifier interface {
    Send(title, body string, priority int, tags []string) error
    Name() string
}
```

支持的通知渠道：
- **NtfyNotifier** - 现有 ntfy 功能重构
- **TelegramNotifier** - Telegram Bot API
- **WebhookNotifier** - 通用 HTTP POST（覆盖 Slack、Discord 等）

### 2. 配置变更 (`config.go`)

新增环境变量：
| 变量 | 说明 | 默认值 |
|------|------|--------|
| `PUSH_PROVIDER` | 通知渠道: ntfy, telegram, webhook | ntfy |
| `PUSH_MARKDOWN` | 是否使用 Markdown 格式 | true |

保留现有变量（向后兼容）：
- `NTFY_SERVER`, `NTFY_TOPIC`, `NTFY_TOKEN` - ntfy 配置
- `PUSH_ENABLE` - 总开关

新增变量：
- `TELEGRAM_BOT_TOKEN` - Telegram Bot Token
- `TELEGRAM_CHAT_ID` - Telegram Chat ID
- `WEBHOOK_URL` - Webhook 地址
- `WEBHOOK_METHOD` - HTTP 方法（默认 POST）
- `WEBHOOK_HEADERS` - 自定义 Headers（JSON 格式）

### 3. 修改 `predictor.go`

- 将 `sendNtfyNotification` 替换为通用 `sendNotification`
- 根据 `PUSH_PROVIDER` 配置创建对应的 Notifier
- 根据 `PUSH_MARKDOWN` 决定是否发送 Markdown 格式内容

### 4. Markdown 格式处理

当 `PUSH_MARKDOWN=false` 时：
- 移除 `**bold**` 标记，保留纯文本
- 移除 `##`/`###` 标题标记
- 移除 `- ` 列表标记
- ntfy: 不设置 `Markdown: yes` header
- Telegram: 使用 `parse_mode=""` 而非 `MarkdownV2`
- Webhook: 在 JSON body 中标记 `markdown: false`
